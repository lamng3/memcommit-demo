MemCommit's behaviour is a set of knobs: which memories leave working memory, how fast they fade, how dreaming resolves conflicts and duplicates, and what reasoning may conclude. Pick a configuration and see what the library did with it.

Every number and every list below was produced by the Python library, over a grid of configurations, by configs_data.py; this page only looks them up. Change a knob and the result, the comparison, and the code for that configuration update together.

About the data

  • Eviction replays two synthetic workloads through the real store. Agent is bursts of trace steps with skewed reuse. Conversation mixes lasting profile facts, dated events that expire, chatter summarized weekly, and premises with plans built on them; it was built to have these properties, so it shows what the semantic knobs do, not that real conversations behave this way. Hit rate is how often a memory an agent used was still in working memory.
  • Forgetting scores a retention curve by how well it predicts which LoCoMo items come up in the next session (ROC AUC on conversations 6 to 10). Higher is better; 0.5 is chance.
  • Dreaming runs the rule-based extractor over a three-session script, with no model.
  • Ontology reasons over eleven stated facts with a small declared ontology.
